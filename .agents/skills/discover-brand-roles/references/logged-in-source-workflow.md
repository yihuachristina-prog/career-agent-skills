# 登录态来源与收藏岗位工作流

本工作流只观察和记录，不在招聘网站收藏、取消收藏、投递、沟通、修改求职状态或联系招聘方。

## 固定来源

每轮覆盖且只按以下七类来源记账：`脉脉`、`猎聘`、`BOSS直聘`、`51job`、`智联招聘`、`LinkedIn`、`企业官网`。搜索引擎只用于定位这些来源，不作为第八类来源。`58同城`不再搜索、统计或推荐。

## 两种运行模式

### 主动登录模式

- 用户主动发起，或在定时运行前明确回复允许登录时启用。
- 优先复用用户已登录的浏览器会话；账号密码、二维码、短信和滑块验证只由用户完成。
- 不读取密码、Cookie、本地存储或其他认证秘密，不绕过验证码和反爬限制。
- 某一来源需要用户完成登录时，记录 `登录待刷新`，继续检查其余来源；用户完成后再刷新该来源。

### 定时无人值守模式

- 由独立的运行前预检任务在雷达开始前 30 分钟主动询问是否启用登录态深扫。
- 到雷达运行时仍无明确回复，则直接使用公开页面、企业官网和 Web 搜索推进，不暂停、不请求人工权限。
- 同一日期使用运行检查点避免重复全量处理；用户迟到回复时，只补做当日登录态增量扫描与收藏状态复核。
- 不假装一个已启动的定时任务可以原地等待用户回复。

运行检查点保存在唯一职位台账同目录的 `.brand-role-radar-run-state.json`，不是第二套职位表。幂等键为 `本地日期 + 来源 + 模式 + 扫描类型`，字段至少包含：预检发出/回复时间、来源覆盖状态、已加载页码或数量、可见/已复核收藏数、首次全量是否完成、最近成功核验时间。每次开始先读、每个来源完成后原子更新；同日迟到补扫复用原检查点，不重复已完成来源。

## 处理顺序

1. 用户手工标绿且已有当前 Word 的岗位。
2. 状态精确为 `用户保留` 的岗位。
3. 七类来源中当前可见的全部收藏/保存岗位。
4. 台账中尚未完成深度评估或需要平台状态复核的岗位。
5. 北京、上海、杭州、广州的新岗位搜索。
6. 招聘主体核验；猎头、招聘机构和匿名客户线索反查同一企业方职位。
7. 企业官网或第二可追溯来源交叉核验，并为通过主体核验的岗位建立公司/业务线招聘情报。

绿色只表示用户已调整、等待吸收；收藏/保存只表示平台内兴趣标记。二者都不等于 `用户保留`、投递授权或岗位仍有效。

## 收藏岗位扫描

首次主动登录试运行必须遍历各平台当前可见的全部收藏分页或懒加载结果，不只读取首屏。以页面显示总数为基准记录 `页面总数 / 已扫描数 / 去重数 / 受限数`；只有四项可对账且六个招聘平台都完成登录态收藏遍历，首次全量扫描才算通过。任一平台受限或部分完成时，在检查点保留 `first_full_scan_pending: true`，把已登录收藏页和本轮辅助页作为 `handoff` 保留用于接续，不得在任务清理时关闭；下一次主动登录模式继续补齐该平台，已完成平台不重复全扫。全部完成后，后续运行采用“新增收藏增量 + 历史收藏状态复核”：

- 新收藏与台账去重后进入硬筛和深评。
- 历史收藏仍复核页面可访问性、招聘状态和关键 JD 变化。
- 平台隐藏、取消收藏或列表消失不能单独证明岗位结束；记录观察差异并寻找原职位页或第二来源。
- 平台明确显示已关闭、停止招聘或职位下线时，记录原文和核验日期；若台账已有投递/HR/面试历史，只更新证据，不回退状态。

每个可见收藏至少记录：平台、平台岗位 ID（可见时）、职位链接、公司、职位、城市、收藏状态、平台流程状态、JD/薪资/日期的可见范围、页面状态、分页或加载范围、台账映射和去重依据。

## 去重与复核

- 优先使用同平台岗位 ID；其次使用标准公司名、标准职位名、城市和规范化链接。
- 同一岗位只维护一个台账主记录。企业官网为主链接；其他平台写入备用链接或备注。
- 猎头、招聘机构和匿名客户职位只有在找到同一企业方职位后才进入深评；保持原岗位编号，把企业方链接设为主链接、猎头页降为备用来源。
- 新岗位和关键事实变化岗位尽量取得第二来源；无法取得时如实标记 `单一来源`，不补写未知字段。
- 同一岗位多平台信息冲突时，保留各自原文和核验日期，在“下一步”写唯一会改变结论的冲突项。

## 平台状态与台账状态

- 台账状态和用户明确操作是主状态；平台显示只作为外部证据。
- 平台明确显示已投递/沟通/面试，可在同一岗位主记录中补充证据，但不得自动外发或替用户做任何平台动作。
- 平台明确显示职位关闭且没有投递历史时，可按共享契约更新为 `已失效`；证据不足时保持原状态并标记待核实。
- 不得回退 `已投递—待反馈`、`HR无回应或失联`、`HR明确拒绝/不合适`、`面试中`、`已结束` 或 `已失效`。

## 覆盖记录

七类来源每轮都必须有一条覆盖结果，状态只使用：`已登录深扫`、`部分完成`、`公开搜索`、`登录待刷新`、`页面受限`、`无结果`。已进入收藏列表但分页或懒加载未遍历完时写 `部分完成`，并记录完成范围；只有实际完成所需搜索或收藏遍历后才可写 `无结果`。登录墙、验证码、页面不可读或未遍历完成不能写成无结果。

首份报告补充：七类来源尝试数、登录态完成数、收藏可见数、收藏已复核数、新增收藏数、历史状态变化数、受限来源及原因。部分来源受限时仍输出其他来源的可验证结论。

# 搜索规则

运行时从共享的 `候选人画像与薪资边界.md` 读取实际参数。本文件只定义解释方式，不保存第二份候选人事实。

## 岗位方向

- 将画像中的岗位方向拆为核心方向、相邻方向和有限 Stretch，分别建立检索词。
- 标题相似不等于匹配；职责必须以品牌 ownership、整合营销或复杂项目管理等画像价值为核心。
- Senior Brand Manager 只在管理范围、经验要求和职责不过配时保留。
- 明确排除画像中的高级管理岗、低配执行岗、校招、管培、实习和纯 Entry Level。
- `Assistant Brand Manager` 可作为目标岗位；普通职能助理不能因 Assistant 关键词误收。

## 城市与聊天榜

- 固定按画像顺序分别搜索北京、上海、杭州、广州；天津不再进入搜索、统计或推荐范围。
- 四城所有达标岗位进入对应工作表。
- 聊天行动榜只展示北京前 5 名；北京不足 5 个时不跨城补位。

## 时间与渠道

- 只把发布时间明确在 90 天内的岗位作为正常候选；只有可信证据明确显示超过 90 天时才按时效剔除。
- 每个城市先覆盖最新发布结果，再至少执行一轮 90 天有效窗口内的存量补扫；不得因已经找到若干新岗位、只查看首批结果或首个结果页而停止。补扫可使用日期范围、翻页、同义岗位词、企业招聘页和搜索引擎交叉定位。
- 90 天内岗位不因“不是本周新发”而降低能力匹配或投递价值；`新鲜度` 只用于同等条件下排序，不能替代完整窗口覆盖。每轮扫描以本轮日期减去台账 `首次发现` 日期，更新四城全部数据行为精确 `N天`；不得把页面发布时间、再次发现日期或静态“今日/近7天”文本当成新鲜度。
- 日期未知可进入 P2/P3，但必须标记 `日期待核实`。
- 企业直招公开 JD 不完整或页面受限时，只要公司、职位、城市和来源线索均可追溯，保留待核验线索；无正文不生成详细匹配与定向选材，职责、薪资和发布日期缺什么记什么。猎头/招聘机构/匿名客户线索还必须找到同一企业方职位，否则结束。
- 不根据相似职位、搜索摘要或常识补写 JD、薪资和发布日期；岗位存在性无法追溯的传闻不收录。
- 固定覆盖来源为：脉脉、猎聘、BOSS直聘、51job、智联招聘、LinkedIn、企业官网。58同城不搜索、不统计、不推荐；搜索引擎只负责定位固定来源。
- 来源路线为：企业官网/企业自有招聘页 → 招聘平台中的企业认证 HR/TA 直招；猎头、招聘机构或匿名客户职位只作为企业线索，反查到同一企业方职位后才进入公司情报和深评，查不到则结束。
- 同一岗位出现多个来源时，以企业直招来源作为主链接，猎头或聚合来源写入备用链接/备注；不得重复建行。
- 主动登录模式先扫描固定平台当前可见的全部收藏岗位；首次运行遍历全部分页或懒加载结果，后续运行新增收藏增量与历史收藏状态复核并行。
- 收藏、取消收藏或收藏列表消失都不等于 `用户保留`、投递授权或岗位结束。平台状态只作为证据，台账状态与用户明确操作优先。
- 新岗位和关键事实变化岗位尽量取得企业官网或第二可追溯来源；只有单一来源时标记 `单一来源`，不得补写未知 JD、日期或薪资。
- 记录实际覆盖与失败原因，不把未覆盖解释为没有岗位。

## 薪资参数

从共享画像读取并分别传递：

- `current_monthly_base_rmb`
- `current_annual_rmb`
- `offer_floor_rmb`
- `listing_max_floor_rmb`
- `listing_min_preference_rmb`

不得把五个参数合成一个“最低年包”。月 Base 与年包独立判断；奖金、绩效和更多发薪月数不能补偿月 Base 降薪。

- 月薪上限低于当前 Base：默认排除。
- 招聘年包上限低于上限门槛：默认排除。
- 年包下限低于偏好且口径完整：默认排除；口径不完整则待核实。
- 月薪区间跨过当前 Base：降级并核实实际定薪。
- 只公布年薪、总包或面议：标记 `月 Base 待核实`。
- 区间异常宽或当前年包位于上段：不因最高值高而判 P1。
- 薪资未知但能力匹配强：可保留为 P2 并待核实。

## 更新

用户明确修改城市、方向、职级、排除条件或薪资后，更新共享画像，再用于两个 Skill。不得只修改本参考文件或从单岗位关键词反推长期画像。

## 信息缺失与连续跟进（2026-09-22增量）

检索覆盖与前台榜单分开。四城、七类来源、最新+90天存量及收藏接续要求不变；不设置每天只找少量岗位或新的分数门槛。使用当前有效画像参数，偏好和优先资格不能升格为硬门槛；同一门槛在初筛与深评共享结论，不重复加码。

发布日期未知不按过期处理，页面失败不按关闭处理，薪数未知不默认12薪或反推年包。薪资脚本 `normalize_salary.py` 返回未知年包并保留可独立判断的月薪边界。未取得JD正文仅为待核验线索，不根据标题计算详细匹配、定向选材或生成简历；已有摘要保留原文及明确缺项。公开信息自行从授权固定渠道补齐并核对同一岗位，不要求用户重贴已有背景；汇报线、口语强度等后续沟通问题不一律变成投递前阻塞。

每个入选岗位复用“核心职责/最强证据/核心风险/下一步”简短回答：为什么值得看、哪段直接或可迁移经历对应、当前最大缺口或待核验项、下一步（投递/核验/跳过）。无实际缺口不强编。Skip依据是已确认规则或事实，未知与真实能力缺口分开。

按来源岗位ID及企业/职位/城市/JD证据关联同岗，平台ID不同不自动另建；标题相似也不自动合并。实质变化更新原行并说明变化。已投递不作新投递对象；用户跳过或终止只有实质变化或用户重启才重新提示，不因检索一遍重置状态。明确关闭退出活跃视图并保留历史，投递/沟通历史单独保留。

复用 `validate_source_coverage.py` 的 `reconcile_observation` 先在内存计算同岗更新，再校验运行清单可选的 `updates`（before/observation/after）。同一来源匹配以规范化URL或具体same_job_evidence为依据；关闭必须有closure_evidence；source_failed、jd_incomplete保持原业务状态并记录缺项，重复命中不算新增。它只验证建议写回，不能代替人工判断同岗身份或企业真实性，也不执行写库。原来源覆盖校验持续使用，未搜索完或有读取错误不得报“无结果”。

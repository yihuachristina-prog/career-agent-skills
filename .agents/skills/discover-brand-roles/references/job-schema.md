# 职位字段与决策规则

本文件细化 `品牌职位台账.xlsx`。状态与跨 Skill 回写以 [共享数据契约](shared-data-contract.md) 为准。

## 四城工作表

工作表严格按北京、上海、杭州、广州排序，列结构完全相同。开启筛选、冻结标题行、保留可点击主链接，并按 `可操作性（灰色已处理/不可操作行最后）→ 公司情报门 → 优先级 → 招聘主体类型（企业直招优先）→ 能力匹配区间中位数 → 新鲜度` 排序。`招聘主体类型`、`企业招聘核验` 和 `公司与岗位情报文件` 是共享契约字段，不建立第二套状态。广州岗位编号使用 `GZ-` 前缀。

### 核心字段

| 分组 | 字段 |
|---|---|
| 身份与状态 | 岗位编号、状态、优先级、最终结论、下一步、结束原因 |
| 岗位来源与主体 | 公司、职位、城市/区域、招聘主体类型、企业招聘核验、来源、原始链接、备用链接、完整JD/快照 |
| 公司情报 | 公司与岗位情报文件 |
| 薪资 | 薪资原文、月薪下限、月薪上限、年包下限、年包上限、月Base判断、薪资判断 |
| 时效与要求 | 发布时间原文、标准发布日期、新鲜度、要求年限、团队管理、核心职责、硬门槛 |
| 初筛 | 能力匹配区间、最强初筛证据、主要风险 |
| 深度评估 | 真实匹配区间、当前简历可见区间、定调后可达区间、最强证据、核心风险 |
| 简历与沟通 | 选用底稿资产ID、定向简历资产ID/文件名、修改说明、首轮话术、投递前检查、协同核查问询文件 |
| 审计 | 首次发现、最近核验、深度评估日期、备注 |

数值列用真实数值，日期列用日期值，岗位编号和资产ID用文本。未知字段留空并在相应判断列标记待核实，不用 0 代替未知。

### 新鲜度字段

- `首次发现` 只在新岗位首次入账时写入，之后不得重置。
- 每轮扫描开始时，以 `Asia/Shanghai` 本轮日期减去 `首次发现` 日期，覆盖更新四城全部数据行的 `新鲜度` 为精确 `N天`；首次发现当天写 `0天`。
- 缺失、不可解析或未来日期写 `待核实`，不使用发布时间反推；原异常值留在备注。
- 排序使用计算所得整数而不是 `N天` 文本的字典序；数值小的在前，`待核实` 在同组最后。
- 发布时间字段仍表示职位页面证据；新鲜度表示入账时长，二者不得混用。

多来源观察不新增平行列或第二张状态表。平台岗位 ID、收藏状态、平台流程状态、页面状态、分页范围、差异原文和核验日期按平台名写入 `备注`；企业官网优先作为原始链接，其他来源进入备用链接。平台与台账冲突时只在 `下一步` 写一个会改变结论的冲突项。

## 数据行状态颜色

对整条岗位记录使用统一的低饱和度行填充，并始终同步文字状态。每轮扫描、回写或重排都审计全部数据行，按以下优先级只保留一个状态色：

- 灰色 `#D9D9D9`：用户确认不投，或系统按共享契约完成猎头企业方核验后结束；统一置底。
- 绿色 `#C6E0B4`：用户手工标记“已调整，等待系统吸收”。
- 淡红 `#F4CCCC`：生成失败或缺少一个会阻塞诚实生成的关键输入。
- 淡黄 `#FFF2CC`：当前 Word 审阅稿已新建或已更新，等待用户复核。
- 白色 `#FFFFFF`：没有上述信号的普通行。

颜色优先级固定为 `灰色 > 绿色 > 淡红 > 淡黄 > 白色`。只有成功吸收用户调整、更新同一岗位当前 Word 并完成台账回写后，才清除绿色并改为淡黄；失败时保留绿色并在“下一步”写明唯一阻塞项。不得把绿色解释成 `用户保留` 或投递授权。现有浅蓝、`#BFBFBF` 或其他未定义数据行填充如果没有独立业务含义，统一按映射改成对应标准色；不改表头、链接字体或其他非状态格式。

用户明确筛选并确认不投时保持状态 `深度评估后不投`，结束原因写 `用户确认不投`，再标灰置底。自动深评产生的 `深度评估后不投` 不自动标灰；必须有用户保存的终止设置或聊天中点名确认。灰色本身不授权删除；用户保存设置后还必须另行发出处理/清理指令，且通过共享契约的路径、状态、历史和资产核验后才能清理。若灰色与 `待用户筛选`、`用户保留`、`定向材料已生成`、`已投递—待反馈` 或 `面试中` 等活跃状态冲突，仍把该行置底并在备注记录“灰色与活跃状态冲突，待用户确认”，不得自动结束、删除或回退。

## 匹配度解释

匹配区间只用于同批排序，必须附证据：

- `80%–90%`：核心 ownership、年限、职级与多数硬门槛有直接证据。
- `70%–80%`：总体可投，有一个可解释缺口或信息待核实。
- `60%–70%`：Stretch，需有意识选择。
- 低于 `60%`：通常不进入候选表，除非用户明确要求探索。

禁止因关键词命中虚增分数；未知项不能自动算作满足。

## 优先级

- `P1`：时效、职级、核心价值、证据和薪资空间均较强。
- `P2`：总体可投，但有一项需核实或可解释风险。
- `P3`：Stretch、回报较低或信息较不完整，仅作备选。
- `Skip`：违反硬过滤或必须失真包装。

初筛优先级仅决定深评顺序，不是首份用户可见报告的最终结论。通过硬筛的 P1/P2/P3 必须完成深评；最终报告中的 Top 5 只包含深评后的 Apply。

招聘主体类型不直接改变候选人的能力匹配，但决定机会能否进入深评和材料阶段。企业官网、企业自有招聘页或企业认证 HR/TA 直招通过公司情报门后进入深评。猎头、招聘机构和匿名客户职位先写 `猎头线索核验中`，只有找到同一企业方职位并把企业链接设为主来源后才能进入深评；否则按共享契约结束。90 天窗口内的存量岗位与新发布岗位使用同一匹配门槛，新鲜度只在其他条件接近时排序。

## 最终报告

- **北京行动 Top 5**：公司、职位、最终优先级、真实匹配区间、最强证据、核心风险、薪资判断和岗位编号。
- **Pending 清单**：岗位编号及一个会改变结论的关键缺失项。
- **深评淘汰清单**：岗位编号、初筛通过理由、深评 Skip 理由。
- **猎头线索核验清单**：找到企业方职位并转入深评的记录，以及因企业未知或未找到同一企业方职位而结束的记录。
- **其他城市摘要**：上海、杭州、广州分别报告 Apply/Pending/Skip 数量；完整结论留在工作表。

不得隐藏“初筛较强但深评后 Skip”的岗位，也不得把仍为 `深度评估中` 的岗位算入最终 Top 5。

## 薪资规则

从共享画像读取实际参数，不在本文件复制候选人数字。

1. 月薪上限低于 `current_monthly_base_rmb`：`月 Base 上限不足`，默认排除。
2. 年包上限低于 `listing_max_floor_rmb`：`年包上限不足`，默认排除。
3. 年包下限低于 `listing_min_preference_rmb`：口径完整时默认排除，口径不完整时待核实。
4. 月薪区间跨过当前 Base：`实际月 Base 待核实`，不能判 P1。
5. 只公布年薪、总包或面议：`月 Base 待核实`，不得反推固定月薪。
6. 当前年包处于区间上段或等于/高于上限：降级并核实。
7. 区间上限超过下限 1.6 倍时默认标记 `区间过宽`。
8. 薪资未知但能力匹配强：可 P2，标记待核实。

薪资影响岗位回报与优先级，不改变能力匹配。进入 offer 阶段时同时检查 `offer_floor_rmb` 与 `current_monthly_base_rmb`，两者不可互相替代。

## 台账验收

- 四表字段顺序一致，只有一个岗位主记录。
- 状态只使用共享契约中的枚举。
- 招聘主体类型、企业招聘核验和公司与岗位情报文件字段存在且四表一致。
- 雷达不回退深度评估或投递状态。
- 企业直招岗位在深评前有情报文件；猎头线索只有找到同一企业方职位后才能进入深评和材料阶段。
- `Apply–P1/P2` 自动审阅稿成功时文件字段非空、下一步为审核审阅稿且整行淡黄；失败时不存在伪文件并按绿色优先规则保留绿色或标淡红。
- `Apply–P3`、`Pending`、`Skip` 未经用户保留时不生成材料、不标“已生成”。
- 定向 Skill 在原岗位行回写，不新增近义列。
- 北京聊天榜最多五个且不跨城补位。
- 北京聊天榜只使用深评后的 Apply；Pending、Skip 和评估失败均不占 Top 5。
- 每城已完成最新岗位检索和 90 天有效窗口存量补扫；结果不能只来自本周新发或首批搜索页。
- 企业直招通过情报门后进入排序；未核验到同一企业方职位的猎头/招聘机构/匿名客户线索已结束且未生成材料。
- 每个城市表中，用户确认不投和其他灰色已处理/不可操作岗位全部使用 `#D9D9D9`，并排在非灰色可操作岗位之后；行内事实、结论和终态信息保持不变。
- 灰色与活跃状态冲突时只置底并写冲突备注，不自动结束、删除或回退该岗位。
- 四城全部数据行的新鲜度已由不变的 `首次发现` 与本轮日期重算为精确 `N天`；异常值写 `待核实`，没有遗留静态相对日期。
- 数据行没有未定义浅蓝、第二套灰色或其他状态色；同一业务信号在四表使用同一标准色。

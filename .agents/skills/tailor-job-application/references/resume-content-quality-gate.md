# 定向简历内容与篇幅质量门

仅在生成或迭代定向简历时读取。雷达自动深评为 `Apply–P1/P2` 并进入审阅稿生成时必须读取；只判断模式不读取、不生成材料。

先执行[候选人已确认的简历写法](candidate-writing-style.md)。这是用户长期要求；本文件的条数与篇幅只是辅助，不授权压缩成熟项目叙述。

## 1. 建立底稿与篇幅基准

1. 盘点所有可读原始简历、岗位族底稿和用户已确认终版，记录资产ID、方向、栏目结构、项目顺序和可见正文文字量。
2. 依次比较岗位价值/岗位族、核心证据在前 1/3 页的可见度、栏目与项目颗粒度、所需改动量和事实核验状态。
3. 为每个岗位选择一个主底稿；其他版本只作为句段补充来源，不形成第二份当前底稿。
4. 用户明确指定版本时优先采用；若有事实冲突或明显不适配，先说明并只追问会改变选择的一项事实。
5. 没有任何可读底稿时，只索取一份可读原始简历，或明确降级为无法核验模板和篇幅的逐条替换稿；不得声称已保持原模板。
6. 同时选择一份成稿标尺：用户确认、实际投递或锁定的同岗位族终版优先；其次才是最接近且事实已核验的完整底稿。记录其正文和渲染页的页数、栏目、简介条数、项目颗粒度与版式参数。

## 2. 以句段为单位定向组合

- 相关性高、事实已确认且表达成熟的原稿句段优先保留，只调整顺序、关键词和衔接。
- 主底稿与JD匹配时，尽量保持用户模板写法；表达不足或叙述重点不匹配时，可以从已核验版本补入完整句段，或在事实边界内重写、重组和调整优先级。重写仍须参考用户材料的颗粒度、完整叙述和专业表达，不能改成标签或提纲；实质取舍在修改说明中交代。
- JD关键词自然对应真实动作与能力。原稿笼统写参与时可以按实际补充负责环节、判断和贡献；不无依据改变全项目分工，不编未参加项目。认知/案例分析按 `why-me-and-readiness.md` 积极表达；短期补不齐项省略。
- 不整份照搬任一原始版本，也不把一个岗位的整套简介、关键词和项目顺序机械复制给另一个岗位。
- 简历正文不主动陈列语言、行业、团队规模等负向缺口；这些风险放入深评、修改说明和投递前检查。简历本身不得用虚构表述掩盖缺口。

## 3. 保持正式简历颗粒度

最终 Word 中至少保留：

- 个人简介围绕JD最重要的业务任务写完整能力陈述，不列具体案例、项目名和案例业绩数字；段落数与节奏沿用用户已确认写法，不机械套3–5条。
- 当前/最近岗位的职责范围、汇报或 ownership，以及品牌、业务或项目边界。
- 重点项目按JD相关性选择；每个核心项目参考用户材料的完整段落与颗粒度，保留业务情境、本人判断、协同推进及结果关系。匹配时尽量保留原写法，需要重写时保持同等展开程度，不为满足固定项目数或2–4条格式合并、删薄原稿。
- 相关度较低但能补充能力边界的经历，每项保留 1–2 条完整事实。
- 教育背景及已确认的职业时间线说明。

不得把完整项目压缩成只有“负责品牌策略、IMC、GTM、协同”等名词的提纲。缺少量化结果时保留真实动作和产出，不编造指标。

按当前用户已确认的职业时间线和锁定段落写工作经历；保留真实任职性质、日期与职责，不使用其他候选人的固定经历或过渡期说明。

## 4. 控制文字量

1. 以主底稿提取出的可见正文字符数作为基准，记录：
   - `底稿文字量`
   - `定向稿文字量`
   - `差异率 =（定向稿文字量 - 底稿文字量）/ 底稿文字量`
2. 默认把差异率控制在约 `±10%`；用户提供已排版模板或更严格要求时，以用户模板为准。
3. 最终有效正文量同时不得低于成稿标尺的 `85%`。低于时必须逐项证明删除内容重复、失实或与目标岗位明显无关；否则恢复完整证据并重做。
4. 超长时先压缩低相关项目、重复背景和同义表达，不删除决定匹配度的关键证据。
5. 过短时优先恢复相关项目的情境、个人动作、协同关系和结果，不用空泛自评凑字数。
6. 无法可靠提取底稿或成稿标尺文字量时，以栏目、项目数和每项要点数对齐，并明确标记“篇幅为结构近似，未完成精确文字量核验”。

## 5. 最终交付与版本

- 所有给用户查看、确认或使用的最终定向简历一律交付可直接打开的 Word `.docx`。
- Markdown 或纯文字只能作为内部中间稿或同一资料包内的内容源，不得作为最终交付、当前资产或唯一可查看文件。
- 即使用户说“只要文字、不用精细排版”，也要把完整文字放入基础、清晰、可编辑的 Word；这表示降低排版复杂度，不表示改成交付 Markdown。
- 使用文档工作流生成并渲染 Word，检查全部页面；不能可靠复刻原模板时，交付基础可读 Word 并说明版式降级。
- 同一岗位只维护一个当前 Word 定向简历资产ID。迭代按 [当前版本与旧稿清理](current-version-retention.md) 暂存并验收新版，正式登记成功后清理旧稿和临时副本，不创建“最终版2”等并行当前资产。
- 当前审阅阶段把 JD 与定向简历放在同一个 Word：首屏先写 `审阅稿，不可直接投递`、岗位元信息、来源、核验日期、完整性、缺失字段和完整可核验 JD，分页后再放定向简历。只有摘要时必须显著标明摘要，不得包装成完整 JD。
- 匹配度、证据等级、Apply/Pending/Skip、风险说明、AI备注和待验证问题只允许在 JD 审阅区或外部材料中出现，禁止进入分页后的简历正文。
- 管理人数默认不写；仅当 JD 明确看重团队管理且真实人数有正向价值时才简洁写入。
- `resume-deliverable-standard.md`、自动审计、视觉验收和标尺比较从首版简历正文开始执行。需要不含 JD 的干净投递稿时，无需等待用户再次确认内容；移除审阅区后复跑同一质量门。
- 每次迭代同步更新投递话术、修改说明、投递前检查和协同核查问询。

## 6. 交付前逐项验收

- 已按candidate-writing-style.md逐段对照用户确认原稿；未用最近未确认的AI稿作为标尺。总字数相近不能弥补关键案例被缩写。
- 个人简介无具体案例名称及案例业绩数字，核心陈述逐项对应JD主任务，且正文有完整事实支持。

- 首要目标已落实：前 1/3 页能清楚回答为何值得给面试，至少两至三项 JD 相关优势在正文有依据；没有因跨行业或缺同业头衔而机械弱化已可支撑的能力表达。
- 用户允许的适度前置认知、行业理解与方法主张已积极呈现，且独立说明中有短期可兑现的准备与追问；不把未来学习或未做项目写成历史成果。
- 已记录主底稿资产ID、文件名、选择理由和文字量。
- 已记录成稿标尺、正文字符量、栏目/项目颗粒度和版式参数。
- 最强竞争力在首屏可见，并逐项对应经历正文的具体支撑；同时交付独立竞争力与快速补强说明。正式简历不出现“已有理解、可迁移基础、正在补足”等内部措辞。
- 相关成熟句段已优先复用；所有新增或改写内容可追溯到已确认事实。
- 重点项目具备情境、本人行动、协同/交付和结果中的必要要素，不是关键词提纲。
- 没有无依据扩大 ownership、指标、预算、团队规模、语言或行业经验。
- 定向稿与底稿的文字量差异符合约 `±10%`，且不低于成稿标尺的 `85%`；或已按规则说明无法精确核验。
- 不同岗位的底稿、项目排序和关键词由各自 JD 决定。
- 原始简历未覆盖，当前资产唯一；新版及正式登记已验收，符合版本清理范围的旧稿已删除并回读，受保护来源和投递/面试材料保留。
- “职业状态”独立栏目已移除；品牌营销顾问（项目制）位于工作经历第一项，定稿正文逐字一致，且禁用的调整期措辞为零。
- 审阅稿中的公司/业务线情报摘要、JD 审阅区与简历正文有显式分页和标题隔离，未把公司推断或岗位要求混入候选人经历。
- 修改说明记录底稿、整段重写、项目增删或重排、能力定位变化、JD 关键词强化、Word 文件名和文字量差异；标点、格式和不改变含义的轻微语序调整不逐句记录。
- 唯一职位台账、简历资产索引和协同核查问询已同步。

## 7. 本次修改范围与实际文件证据（2026-09-22）

在既有“修改说明/投递前检查/验收记录”复用一份内部记录，保存本次JD、底稿、认可依据、源文件版本、修改范围及必要缺口；不新增用户需填的表单、评分或报告。

生成前先判定问题属于事实、选材、结构、表达或版式。同岗位从唯一当前稿及最新已确认段落接续；局部修改只开放必要段落。结构确有错误时联动修复并说明理由。用户锁定核心项目不得自行替换；未锁定选材用同一份JD—证据映射解释。正文来源按公司/项目/阶段分别核对职责、预算、结果、时间和归因，不将多个项目凑为一个案例。

在原 `audit_resume_delivery.py` 的既有运行中加 `--context <本岗位验收记录.json>`，读取其 `resume_review`：可复用 `sources`（path/sha256）、`locked_passages`（source/quote）、`blocks`（anchor/employer/sources/required_evidence/end_before/forbidden_patterns/check_numbers）及局部改稿的 `local_edit`（before_paragraphs/allowed_before_indices）。仅记录当前改动实际需要核验的项，禁止为凑字段逐项编造。`required_evidence` 每组允许同义表达；由原段承载的判断、动作、协同、结果确定，不是通用关键词模板。局部改稿比较整稿差异，防止无关已认可段落回退。块的结束标题必须限定到同一项目；数字核对不能只查全篇“出现过”。

自动检查能发现来源版本变化、正文含审阅标记（包括表格）、项目公司归属、核心段落丢失、约定证据关系丢失及局部修改越界。它不能自行证明原始来源真实、改写语义等价、每条事实已映射或颗粒度合格；仍逐段对照原文，并把主要能力在简介、项目选择、排序、具体文字四处落实。固定字数比例仅作异常提示，用户当次已确认的篇幅要求优先，不用加字掩盖关键证据被删薄。

实际文件依次回读、自动审计、逐段保真检查、全部页面渲染目检；内容/结构与视觉结果分别记录。文件生成、成品检查通过、用户确认、实际投递分别记在现有字段/备注，不能互相推定。未核实关键事实或任何检查失败，保持审阅/受阻状态，不写可直接投递。干净正文无内部检查、占位符、待核验标记及其他岗位残留。

沿用现有停止条件及当次已配置修订上限；不因本次升级无反馈反复改稿。当前安装规则未设数值轮数时，不谎称有既定数字：仅针对具体失败修正并复核受影响项；重复失败无新证据就记录准确未通过项，不将模型自评分当通过。

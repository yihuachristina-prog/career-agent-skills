# 协同核查问询规范

在首次生成或每次更新定向简历后，同步生成一份与岗位编号绑定、可直接复制给其他 AI 大模型的核查问询。问询用于获得独立第二意见，不替代用户决策，也不授权自动发送。

## 必须包含的材料

1. 岗位编号、招聘主体核验、公司、职位和完整 JD；缺失字段明确标为未知。
2. 同岗位公司与岗位情报摘要：当前招聘版图、经营/业绩、组织/汇报、竞品、岗位 scorecard、来源等级和置信度。
3. 本轮深度评估结论、三个匹配区间、最强证据和核心风险。
4. 当前定向简历的完整文本；若只提供文件路径，必须同时给出可复制正文。
5. 本轮修改说明及对应证据来源。
6. 候选人的事实边界：不得新增未提供的经历、指标、ownership、语言或管理经验。

## 核查任务

要求外部模型独立完成并按固定顺序回答：

1. 最终结论：Apply–P1/P2/P3、Pending 或 Skip，并说明置信度。
2. 真实匹配度与当前简历可见匹配度区间。
3. JD 最重要的 3–5 项要求及简历证据覆盖。
4. 任何夸大、事实跳跃、身份拔高或无法由材料支持的表述。
5. 个人简介是否直扣JD核心任务，以完整能力陈述呈现且没有具体案例名和案例业绩数字；正文是否按candidate-writing-style.md保持颗粒度和完整叙述，原稿与JD匹配时是否尽量保留模板写法，尤其检查即使字数相近仍出现的结构性缩减。
6. 不改变真实经历前提下，最多 5 条最小修改建议。
7. 一个最需要用户补充或面试验证的问题；没有则写“无”。
8. 与原深评结论的分歧，以及分歧来自事实、权重还是风险偏好。
9. 公司情报中的事实、推断和未知是否分层；岗位 scorecard 是否有从公司业绩、招聘数量或竞品动作过度推断 KPI 的问题。

## 去偏要求

- 明确告诉外部模型：原深评只是待核查输入，不是标准答案。
- 不要求对方迎合原评分；结论必须引用 JD 与简历中的具体证据。
- 未知信息不能默认满足，也不能直接当作确认缺口。
- 公司经营事实、组织推断和候选人经历是三类证据，不得相互替代。
- 不允许建议虚构经历、业绩、预算、语言水平、团队规模或行业 ownership。

## 文件与迭代

首次生成时创建一个稳定的问询文件并关联岗位编号。后续简历修改时更新同一问询文件，使其始终对应当前定向简历；不得为每轮修改建立多个并行的“最终问询”文件。聊天中同时给出可直接复制的正文。

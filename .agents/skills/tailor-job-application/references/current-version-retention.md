# 匹配完成后只保留最新版本

2026-09-14更新：本规范用于活跃岗位的旧版本清理。明确失效、HR无回应或失联及用户灰色终止岗位的整包清理，优先执行[文件包命名与每周终止清理](package-maintenance.md)，其常设授权覆盖下文同范围的HR历史材料保留限制；沟通和投递历史信息保留在台账。


用户于 2026-09-11 确认本项目采用此规则，取代匹配产物长期归入 `history/version_history` 的旧做法。

## 范围与保留对象

- 每次获授权的岗位匹配、材料迭代或雷达回写完成后，清理本轮处理岗位同一用途的已被替代版本，以及本轮使用的共享台账副本。多个岗位各保留自己的最新版；独立补强说明、话术、英文配套稿和同源 Markdown 按用途分别保留当前版本，不合并成一份文件。
- 正式台账固定为 `data/品牌职位台账.xlsx`，资产索引使用同目录的 `简历资产索引.xlsx`。最新版依据正式记录、交付验收和实际文件共同确定，不以修改时间或“最终版”文件名猜测。
- 清理对象包括旧台账/资产索引副本、旧审阅稿、单岗位简历旧稿、同用途配套材料旧稿，以及确认已发布且不再被引用的多轮暂存、导出、预览和临时备份文件。转换为干净投递稿后不长期保留旧审阅容器；其中 JD、来源与必要情报必须已独立保存。
- 保留原始简历、岗位族底稿、经历证据库、完整能力库、JD/来源材料及已投递、招聘沟通或面试材料（包括有用途的历史投递版本）。沟通历史保护包括 `HR无回应或失联`、`HR明确拒绝/不合适`，不能只识别“已投递/面试中”字样。`sources/` 和同步原件保持只读。证据库引用的旧稿在完成可追溯来源保全前不删。
- 全项目存量清理只在用户明确要求时执行；普通单岗匹配不扩大为删除其他岗位或整个日期目录。用户对已明确范围的授权无需重复询问；新的目录、用途不明或唯一版本冲突只暂停相关项。只读比较、历史演练、不写库模式不触发清理。

## 发布与清理顺序

1. 定位正式台账、资产索引和各用途当前文件，记录岗位/资产 ID、路径与 SHA-256；读取投递、面试、来源引用及待写回状态，建立保留清单。
2. 在本轮暂存区完成新版本。覆盖前可保留一份临时回滚副本；发布前不删除现有可用文件。临时回滚仅用于本轮事务，不作为完成后的长期历史。
3. 新版通过内容、结构和适用的逐页渲染验收后，检查源文件哈希未变，再写回正式位置和唯一索引。正式文件回读、路径、哈希、岗位/资产唯一性及状态不回退全部通过后，才进入清理。降级交付、写回失败、文件占用、并发变化或缺少唯一当前稿时，保留恢复所需文件并报告具体阻塞。
4. 为每个旧文件生成清单：绝对路径、大小、SHA-256、所属岗位/用途、对应当前文件和判旧依据。目录名或文件扩展名不能单独作为删除依据；检查候选及其父路径无越界、符号链接或重解析点，排除保留清单及当前仍引用的文件。混合目录逐文件处理，不能直接递归删除 `outputs/`、`working/`、`history/` 或 `version_history/`；仅在所有内容均已核对后移除空子目录。
5. 删除前重新核对候选清单、保留文件与源哈希，并确认实际执行账户；沙盒账户的回收站不能代替用户桌面账户的回收站。按当次已授权的方式删除精确文件，通常移入用户回收站；回收站失败不静默改成永久删除，不清空用户回收站。永久删除必须有对应授权且在回执明确不可从回收站恢复；本项目已有明确存量清理授权时按该授权范围执行，不重复索取同一确认。若安全审查拦截执行，停止相关批次，补充证据或请求所需批准，不通过换命令绕过。
6. 独立回读验证每个候选原路径已不存在、保留文件仍存在且哈希未变、正式台账/索引没有悬空引用。声称“已入回收站、可恢复”前必须核验回收站条目的原路径与文件身份；仅 API 返回成功或源路径消失不足以证明可恢复。未核验到时只报告实际能确认的删除结果与恢复状态。
7. 清理本轮成功事务的暂存、导出和临时回滚副本，保留精简回执（路径、哈希、结果、失败项，不保存旧稿全文）。部分失败如实报数并留下精确待办；不得把尝试数当成功数，不得以忽略读取错误后的空集合声称清理完成。

## 验收与典型边界

- 成功迭代：新版及正式登记已验收，旧稿逐文件清理，当前路径稳定，保留文件哈希复核通过，旧稿不再归入长期版本目录。
- 新版验收失败、缺唯一当前稿或写回未完成：本轮清理为零；保留旧当前文件和恢复所需临时副本，标明待处理。
- 混合历史目录：其中的 JD、原始资料、来源证据及已投递/面试版本保留，只清理已核验被替代的匹配产物。
- 只读匹配或其他岗位仍有未完成任务：不触发相应文件的清理。
- 汇报分开列“规则更新/结构校验”和“实际文件清理”。未真实执行清理时，不声称存量旧稿已删除或完整端到端试运行通过。

2026-09-22补充：作为本次历史质量对照的用户认可稿属于保留对象，即使不是当前投递资产也不得清理或覆盖。它们不构成第二份当前稿；在已有修改说明记录样例身份和认可依据。

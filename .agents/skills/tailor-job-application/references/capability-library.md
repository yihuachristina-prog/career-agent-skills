# 完整个人能力库与岗位问题匹配

## 目的和入口

所有定向简历以尽快获得首轮面试为目标。先按“我的能力 × 岗位问题”判断，再选择模板。能力库维护不要求具体 JD，不经过公司核验门。用户说“汇总所有简历/建立个人能力库/把这版更新进经历库”时进入本模式；“仅比较/仅审校/暂不入库”不写库。

使用现有正式 `经历证据库.xlsx`，保留稳定事实ID；`个人能力库.docx` 是完整可编辑阅读稿，`个人能力库.md` 为同源检索稿。完整库含经历、个人实践、认知方法、能力、不同表述与来源，不能以摘要、标签或单个 JD 的选材代替。详细表述和来源登记在原工作簿中，不建立另一个事实权威。

## 每次先读取

1. 当前任务最新用户事实与更正，当前画像和完整能力库版本。
2. 原资产索引及相关原始材料、回传稿、已确认项目说明。
3. 同项目中直接相关的任务和附件，尤其是新实践、职责补充及事实修正；任务工具不可用时读已落盘产物。记录采用的版本，避免重复询问。

其他任务助手自拟内容、朋友案例和 JD 均为参考，不自动成为本人事实。正在编辑的其他任务产物只读，写回前再查当前版本。原始和同步来源保持只读。

## 数据结构

在原工作簿保留经历证据表，按需要增加：

- 能力索引：能力ID、能力说明、能解决的问题、性质、事实/实践/认知来源、迁移逻辑、可用表达和边界。
- 表述来源：表述ID、原句、关联事实或能力、原来源ID与位置、适用场景、用户确认/原稿/AI衍生性质、当前使用状态。
- 来源清单：来源ID、路径、哈希、格式、个人材料类别、读取/归并状态、排除理由及重复来源关系。
- 更新记录：用户指令、日期、版本、新增/补充/修正/重复/冲突/历史替代及影响范围。

能力性质和事实状态分别保存。历史成果、当前认知、自主实践、迁移推理、学习计划分开；认知和观点可来自明确用户陈述、可说明的判断和方法，不强制绑定同行业任职。

`用户确认底稿` 是已确认材料来源的旧枚举：核对可定位原件及确认依据后可用于相关事实，不机械当成缺失；核对过程入更新记录，不批量无依据改状态。可定位用户原稿的一致记载可作为历史事实依据，无冲突时不反复确认；仅AI衍生的新职责或新数字仍需事实依据。

## 全量汇总与增量吸收

先枚举索引、已知原件及同项目相关材料，再逐份提取正文并比较差异。相同哈希只处理一次，保留各路径；同义表述关联同一事实，实质不同表述保留。不同项目、统计期、预算组成和个人/团队结果不得拼成新业绩。

事实E、能力C、经历J、来源S的已有ID必须复用，不因文件排序或模板切换重编；新记录在现有编号后追加。表述P按原句去空白并转小写后的SHA-256前12位命名；修改后的实质新句子另建P，保留旧句及关联。同一来源先按路径、哈希和内容确认身份。

新增资料分为新事实、细节补充、表达改进、认知/实践、纯重复、冲突。原稿删去内容不等于总库删除。用户明确更正时保存旧值和替代依据；未解释的关键冲突只暂停对应主张，其余继续。重复导入不得增加重复事实或表述。

完整 Word 与 Markdown 至少有能力总览、任职与项目全记录、认知与个人实践、按问题检索的能力卡、不同表述、指标/职责口径、待核实与未来补强、来源覆盖和更新说明。表述很长时可作正文附录；源表保留全部有价值版本。

输出发现候选数、确认为个人材料数、读取数、哈希去重数、归并数、排除与受限数。未读完、旧附件不可访问或无法解析时如实标部分完成，不以枚举或抽样代替完整归并。交付后按用户指定新材料增量维护，不要求重新收集全部原件。

## 全库匹配

对每项核心 JD 要求记录：业务问题/预期结果、重要性依据、全库相关能力与出处、当前简历是否呈现、迁移解释、拟用表达与补强动作。模板没写不等于能力缺失；资料未知不等于不会。

先识别两至三项最强的面试邀约理由，再从全部版本提取经历。认知与方法积极计入，缺同行业职位不单独构成淘汰依据；不可替代门槛须有 JD/招聘方或工作实质依据。保留真实匹配、现稿可见、定向表达可达三类判断，未来学习完成度另列，匹配分数不等于获面试概率。

随后执行 [为什么是我与快速补强](why-me-and-readiness.md)，生成全篇有支撑的简历和独立说明。能力库更新本身不改其他岗位简历、台账阶段、薪资城市或全局记忆。

## 保存与验收

正式写回前备份，检查来源版本未变，写回后回读与哈希核对。同源 Word/Markdown 与结构化表标相同版本；所有可见 Word 文字用微软雅黑并逐页渲染。新表使用原工作簿风格并保留旧表内容。更新回执列新增、变化、重复、冲突及影响能力。

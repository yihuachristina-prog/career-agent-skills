# 证据与决策标准

## 公司情报先行门

在计算匹配度前先读取同岗位 `公司与岗位情报.md`：

- 企业身份、岗位存在性或核心 JD 无法核验：不计算可投结论，不生成材料。
- 猎头、招聘机构或匿名客户线索未找到同一企业方职位：按情报规范结束，不用高薪或关键词匹配覆盖来源风险。
- 企业直招岗位的汇报线、业绩或竞品单项未知：可继续，但扩大结论区间并降低置信度。
- 岗位 scorecard 中的业务问题和 KPI 假设必须保留来源与置信度；不能把推断当硬门槛，也不能把公司业绩当作候选人成果。

## 证据等级

| 等级 | 定义 | 可写入简历 | 处理 |
|---|---|---:|---|
| A | 同类结果、相近规模且有直接 ownership 的已确认经历 | 是 | 高可见呈现 |
| B | 相邻场景或可迁移能力，有已确认项目支撑 | 是 | 真实转译，不写成直接经验 |
| C | 可说明的当前认知、方法与个人实践，或有基础且能迅速准备的岗位分析 | 按性质 | 当前能力可积极表达；未完成作品不写成已完成，短期补不齐则从简历省略 |
| D | 事实未知、冲突或确有缺口，需要分别诊断 | 按状态 | 未知不等于不会；冲突主张停用，真实缺口仅在内部说明 |

能力性质与事实状态分别记录。A/B历史事实须有确认依据；用户确认底稿核对后可用。C类的观点、方法、个人实践可以是当前能力，不要求先有同行业职位。AI/学习计划不得制造过去经历。按 [能力库规则](capability-library.md) 和 [为什么是我](why-me-and-readiness.md) 处理积极表达、正文支撑及补强。

## 先行淘汰项

- 明确要求且不可替代的行业/产品 ownership
- 必须独立完成的作品或手艺
- 证照、地点、语言、年限、管理权限等硬门槛
- 关键事实需要夸大才能满足

材料不足时为 Pending；事实确认缺失且属于岗位核心时为 Skip。

## 三种匹配度

按以下维度判断，不机械求和：

| 维度 | 参考权重 |
|---|---:|
| 岗位核心结果与 ownership | 30% |
| 可迁移职能能力 | 25% |
| 直接项目证据 | 25% |
| 行业/产品情境 | 10% |
| 工作方式与执行模式 | 10% |

分别输出：

- **真实匹配度**：全库实际能力、当前认知与合理迁移对岗位问题的适用性。
- **当前简历可见匹配度**：所选现有底稿能否快速展示证据。
- **定调后可达匹配度**：通过真实重排与有依据的能力表达能达到的呈现水平。未来练习完成度另列，不把计划等同成果，也不把分数当面试概率。

三个区间都以“公司情报支持的岗位 scorecard + 完整 JD”为岗位侧输入。若 scorecard 与单条 JD 冲突，保留两种原文并指出冲突，不自行选择对候选人更有利的一种。

区间解释：

- `80–100`：强匹配，多条 A 级核心证据。
- `70–79`：可信匹配，A/B 级证据足够，无核心淘汰项。
- `60–69`：相邻/Stretch，需结合回报和竞争成本。
- 低于 `60`：弱匹配，通常不优先。

材料不完整时扩大区间并降低置信度，不报单点。

## 决策

- `Apply–P1`：强匹配、岗位价值高、简历可在真实证据内充分证明。
- `Apply–P2`：可信相邻岗位，有一个清楚的风险。
- `Apply–P3`：可以成立但回报或优先级较低。
- `Pending`：只缺一个会改变结论的关键材料或事实。
- `Skip`：核心依赖确认缺失的不可替代能力，或必须失真包装。

其他岗位更优只改变优先级，不把一个可投岗位改成 Pending。

## 薪资与投递价值

从共享画像读取：

- `current_monthly_base_rmb`
- `current_annual_rmb`
- `offer_floor_rmb`
- `listing_max_floor_rmb`
- `listing_min_preference_rmb`

薪资不计入能力匹配度，但可改变优先级或最终是否值得投：

- 月薪上限低于当前 Base：Skip。
- 招聘年包上限低于上限门槛：默认 Skip。
- 招聘年包下限低于偏好且口径完整：默认 Skip；口径不完整可 Apply–P2 并核实。
- 月薪区间跨过当前 Base：最多先判 Apply–P2，并核实固定月薪。
- 只写年薪、总包或面议：标记 `月 Base 待核实`，不得反推。
- 当前年包处于区间上段或区间异常宽：降级并核实。
- 薪资未知但能力强：可 Apply–P2，不把能力判断改为 Pending。
- Offer 阶段同时检查年包底线与月 Base 底线，任一不达标即不满足当前要求。

## 文件验收

- 同岗位公司与岗位情报文件存在，包含主体、招聘版图、经营、组织、竞品、scorecard、候选人证据映射和来源清单。
- 猎头/匿名客户岗位已核验到同一企业方职位；否则没有生成定向简历。
- 首次定向副本已另存生成；后续修改保持同一岗位资产ID和当前文件引用，未创建并行有效副本。
- 原始简历、岗位族底稿和其他岗位版本未覆盖。
- 新增历史主张追溯到已确认事实；认知/方法说明依据。全库强能力没有因模板遗漏而漏评；首屏主张都有正文支持。
- 有限扩写没有无依据扩大 ownership、指标、职责范围、团队规模、语言水平或能力熟练度。
- 公司情报与 JD 共同指向的 3–5 项岗位价值在简历前 1/3 页可见。
- 首版简历正文即逐项执行 `resume-deliverable-standard.md`；公司情报摘要与 JD 前置审阅稿还要执行 `radar-review-package.md` 的容器、来源和隔离规则。
- 最终有效正文量默认保持在底稿约 ±10% 内，同时不少于成稿标尺的 85%；低于时已有逐项、可核验的删除理由。
- 核心项目保留背景/目标、本人判断与职责、关键动作与协同、结果与沉淀的完整证据链。
- 简历正文不含证据等级、匹配结论、风险辩护、AI 备注或“不扩大为”等内部判断。
- 文档栏目、信息层级和主要视觉版式符合选定底稿或用户确认模板。
- 多个岗位的简历分别依据各自 JD 调整，没有批量套写同一组关键词或经历排序。
- 没有把 AI 辅助写成过去经历。
- Word 已渲染并逐页检查，无缺字、重叠、重复或分页异常。
- 干净投递稿已与成稿标尺逐页比较；预计用户仅需 20–30 分钟核对事实与偏好，不需要重新搭结构或扩写。
- 协同核查问询已随当前定向简历同步更新，可供其他模型独立复核。
- 简历资产索引与唯一职位台账已回写。

2026-09-22执行澄清：JD“优先/加分”不当硬门槛，未知不当确认不符合。三种匹配区间及既有权重仅为内部参考，不作为必须填满的表单或新增筛选层；没有可复核基础就不填数字，沿用既有字段以证据与行动说明。入选判断复用核心职责、最强证据、核心风险、下一步回答四项行动问题；不必为P2强行制造风险。
